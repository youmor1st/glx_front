# Логика входа в систему

## Обновленная логика аутентификации

Система теперь работает по следующему алгоритму:

### 1. Автоматическая проверка Quick Login

Когда пользователь открывает страницу входа в Telegram Mini App:

1. **Проверка Telegram WebApp**: Система проверяет, запущено ли приложение в Telegram
2. **Получение данных пользователя**: Извлекает данные Telegram пользователя
3. **Автоматический Quick Login**: Пытается войти через `/auth/quick` endpoint
4. **Показ загрузки**: Отображает индикатор "Проверяем быстрый вход..."

### 2. Успешный Quick Login

Если Quick Login успешен:
- Пользователь автоматически входит в систему
- Перенаправляется на dashboard
- Никаких дополнительных действий не требуется

### 3. Неудачный Quick Login

Если Quick Login не удался (пользователь не привязан):
- Показывается форма "Первый вход"
- Пользователь вводит логин и пароль
- При успешном входе Telegram ID привязывается к аккаунту
- Доступна кнопка "Попробовать быстрый вход снова"

### 4. Дополнительные режимы

- **JSON Login**: Для администраторов без Telegram
- **Telegram Login**: Альтернативный способ входа через валидированные initData

## API Endpoints

```typescript
// Быстрый вход (для уже привязанных аккаунтов)
POST /auth/quick

// Первый вход с привязкой Telegram ID
POST /auth/login

// Вход через валидированные Telegram данные
POST /auth/telegram-login

// JSON вход без Telegram (для админов)
POST /auth/login-json
```

## Пользовательский опыт

1. **В Telegram Mini App**: Автоматическая проверка → Quick Login или форма входа
2. **В браузере**: Показ формы входа с выбором режима
3. **После первого входа**: Все последующие входы через Quick Login

## Технические детали

- Используется `isCheckingQuickLogin` state для управления UI
- Все формы скрываются во время проверки Quick Login
- Показывается индикатор загрузки с анимацией
- Обработка ошибок с понятными сообщениями
- Возможность повторной попытки Quick Login
